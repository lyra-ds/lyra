# Phase 2 — UI Design Contract

> Visual and interaction contract for the `@lyra-ds/styles` package. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Nature of this phase (read first):** This phase ships a **pure-CSS, zero-JavaScript** package. It designs **no new UI**. The entire visual system is **already locked and pixel-final** in `handoff/tokens/*.css` and `handoff/components/**/*.css`. This UI-SPEC therefore **documents the existing, locked design contract** that the packager must reproduce **byte-faithfully** — it does NOT invent spacing/typography/color values. Every value below is carried over **verbatim** from the handoff and is the parity target (STY-06). "Pixel-perfect fidelity" means: if a value here disagrees with `handoff/tokens/`, the handoff wins and this doc is wrong.

## Design System

| Property | Value |
|----------|-------|
| Tool | none (custom, CSS-first — Tailwind & shadcn-as-framework are locked OUT) |
| Preset | not applicable (no shadcn init; `components.json` intentionally absent) |
| Component library | none in this package — `.lyra-*` classes are the public style API; React wrappers land Phase 3/4 |
| Icon library | none in this package (icons are React/Lucide, Phase 3 — `components/icons/` has no CSS) |
| Font | Plus Jakarta Sans (sans/display) + JetBrains Mono (code) — **PEER install via `@fontsource/*`, NOT embedded, NO CDN at runtime** |

**shadcn gate:** Not run. Rationale: the design system already exists, is locked, and is the deliverable itself. The project explicitly locks OUT Tailwind and shadcn-as-a-framework (CLAUDE.md constraints). shadcn appears ONLY as an **opt-in compat layer** (`compat-shadcn.css`, mapped below) that stays outside the default entry. Initializing shadcn would contradict the locked CSS-first architecture.

**Entry `@import` order (verbatim from `handoff/styles.css` — the packaged `styles.css` MUST reproduce this order exactly):**

```
tokens/fonts.css → tokens/colors.css → tokens/typography.css → tokens/spacing.css
→ tokens/effects.css → tokens/brand.css → tokens/base.css
→ components/buttons → forms → display → navigation → feedback → files → data
```

`tokens/compat-shadcn.css` is **NOT** in this chain — it is an explicit opt-in subpath only (STY-05).

**⚠ Fonts / no-CDN divergence (executor MUST handle):** The handoff `tokens/fonts.css` currently contains a **Google Fonts CDN `@import url(...)`**. Runtime CDN dependency is **forbidden** (CLAUDE.md: "nenhuma dependência de CDN em runtime") and fonts are **peer** via `@fontsource/*`. The shipped `tokens/fonts.css` must therefore **NOT carry the CDN `@import`**. Options (Claude's Discretion per CONTEXT): ship an empty/comment-only `fonts.css` that documents the `@fontsource` peer install, or a `@font-face`-free stub. `fonts.css` carries **no tokens**, so it is exempt from the 209-token parity count either way. This is the one place the package intentionally **diverges** from the handoff bytes.

## Spacing Scale

Source of truth: `handoff/tokens/spacing.css` (4px grid). Values are FINAL — reproduce verbatim. Standard 8-point-adjacent scale with 4px granularity; the DS uses a fuller ramp than the generic template default, so the full ramp is the contract.

| Token | Value | Multiple of 4 |
|-------|-------|---------------|
| `--space-0` | 0 | ✓ |
| `--space-1` | 4px | ✓ |
| `--space-2` | 8px | ✓ |
| `--space-3` | 12px | ✓ |
| `--space-4` | 16px | ✓ |
| `--space-5` | 20px | ✓ |
| `--space-6` | 24px | ✓ |
| `--space-8` | 32px | ✓ |
| `--space-10` | 40px | ✓ |
| `--space-12` | 48px | ✓ |
| `--space-16` | 64px | ✓ |
| `--space-20` | 80px | ✓ |
| `--space-24` | 96px | ✓ |

**Corner radii** (`--radius-xs` 4px, `--radius-sm` 6px, `--radius-md` **10px** = Lyra default control radius, `--radius-lg` 14px, `--radius-xl` 20px, `--radius-full` 999px). `--radius-md` is white-label overridable via `--brand-radius`.

**Control sizes:** `--control-sm` 32px, `--control-md` **40px** (default), `--control-lg` 48px. **Layout:** `--container-max` 1200px, `--sidebar-width` 260px, `--content-gutter` = `--space-6`.

Exceptions: `6px`/`10px`/`14px`/`20px` radii and `12px`/`20px`/`40px` spacing steps are **not** strict 8-multiples but ARE part of the locked 4px-grid ramp — they are canonical, not violations. The gsd-ui-checker "multiples of 4" rule is satisfied (every value is a multiple of 4); do NOT flag the non-8 steps.

## Typography

Source of truth: `handoff/tokens/typography.css`. Type scale is 1.250 major third, base 16. Values FINAL — reproduce verbatim. The DS ships a full scale; the four semantic roles below are the primary contract, with the full ramp and composed semantic styles retained.

| Role | Composed token | Size | Weight | Line Height |
|------|----------------|------|--------|-------------|
| Body (UI default) | `--body-font` | `--text-base` 14px | `--weight-regular` 400 | `--leading-normal` 1.5 |
| Body strong / Label | `--body-strong-font` | 14px | `--weight-semibold` 600 | 1.5 |
| Heading (h3) | `--h3-font` | `--text-xl` 20px | 600 | `--leading-snug` 1.3 |
| Display | `--display-font` | `--text-5xl` 48px | `--weight-extrabold` 800 | `--leading-tight` 1.15 |

**Full scale (all must ship, exact px):** `--text-xs` 12, `--text-sm` 13, `--text-base` 14, `--text-md` 16, `--text-lg` 18, `--text-xl` 20, `--text-2xl` 24, `--text-3xl` 30, `--text-4xl` 38, `--text-5xl` 48, `--text-6xl` 60.

**Weights (all ship):** regular 400, medium 500, semibold 600, bold 700, extrabold 800. **Line heights:** tight 1.15, snug 1.3, normal 1.5, relaxed 1.65. **Tracking:** display −0.03em, heading −0.02em, normal 0, caps 0.08em.

**Composed semantic styles (ship verbatim):** `--display-font`, `--h1-font`, `--h2-font`, `--h3-font`, `--body-font`, `--body-strong-font`, `--caption-font`, `--overline-font`, `--code-font`.

**Families:** `--font-sans` & `--font-display` = `"Plus Jakarta Sans", system-ui, …` (white-label overridable via `--brand-font`); `--font-mono` = `"JetBrains Mono", ui-monospace, …`. Fonts are peer (see Design System note).

> Note for gsd-ui-checker: the "3–4 sizes / 2 weights" template guidance is a **greenfield** guardrail. This phase documents a **pre-existing, locked** DS whose declared surface is the full ramp (a design-system token contract, not a single screen). The four-role table above is the primary-usage contract; the full ramp is the parity target.

## Color

Source of truth: `handoff/tokens/colors.css` (+ `[data-theme="dark"]` overrides). 60/30/10 mapped to the semantic surface/accent tokens. Light default; dark via `[data-theme="dark"]` on `<html>` (STY-03, no rebuild).

| Role | Token (light) | Value (light) | Value (dark) | Usage |
|------|---------------|---------------|--------------|-------|
| Dominant (60%) | `--surface-page` | `--slate-50` `#F8FAFC` | `--night-950` `#0E1023` | Page background |
| Secondary (30%) | `--surface-card` / `--surface-raised` | `#FFFFFF` | `--night-900` `#121430` / `--night-800` `#1C1F42` | Cards, raised panels, nav, sidebar |
| Accent (10%) | `--accent` | `--indigo-600` `#5B5BD6` | `--indigo-500` `#6E6ADE` | See reserved list below |
| Destructive | `--danger` | `--red-600` `#DC2626` | `--red-500` `#EF4444` | Destructive actions/state only |

**Accent reserved for (explicit — never "all interactive elements"):** primary buttons (`--accent` fill + `--on-accent` text), focus ring (`--focus-ring` / `--shadow-focus`), active/selected nav & tab states, links (`--text-link`), accent borders (`--border-accent`), and `--accent-soft`/`--accent-soft-text` chips/selections. Hover/active tiers: `--accent-hover` (indigo-700 light / indigo-400 dark), `--accent-active` (indigo-800 / indigo-300).

**Status colors (semantic, ship verbatim, light → dark):** success `--green-600 #16A34A` → `--green-500 #22C55E`; warning `--amber-600 #D97706` → `--amber-500 #F59E0B`; danger `--red-600 #DC2626` → `--red-500 #EF4444`; info `--blue-600 #2563EB` → `#3B82F6`. Each has `-soft` and `-text` variants (see source; dark uses translucent `rgba(...)` softs).

**Text ramp:** `--text-primary` slate-900→night-100, `--text-secondary` slate-600→#C3C8E8, `--text-muted` slate-500→night-300, `--text-faint` slate-400→#6C739E, `--text-inverse`, `--text-link` indigo-600→indigo-300.

**Borders:** `--border-default` slate-200→night-600, `--border-strong` slate-300→#3A3F6E, `--border-accent` indigo-600→indigo-400.

**Base scales (raw, ship verbatim):** indigo 50–950 (11), slate 50–900 (10), night (950/900/800/700/600/300/100), plus green/amber/red/blue semantic hue stops. **Overlays:** `--surface-overlay` `rgba(15,23,42,0.48)` → `rgba(8,9,24,0.64)`.

**Dark-theme elevation rule (from `effects.css`):** dark mode zeroes `--shadow-xs`/`--shadow-sm` (`none`) and relies on **borders, not shadow**, for elevation. Preserve this — it is a deliberate visual contract, not a bug.

## White-Label Brand Contract (STY-04 — core interaction contract of this phase)

Source of truth: `handoff/tokens/brand.css`. Inert until `[data-brand]` is present. A consumer re-brands by defining **4 input tokens**; the entire accent group is **derived via `color-mix(in oklab, …)`** — no rebuild, works in light AND dark.

| Input token | Required? | Default | Purpose |
|-------------|-----------|---------|---------|
| `--brand` | **required** | — | Brand primary color |
| `--brand-contrast` | optional | `#FFFFFF` | Text/foreground on brand fills (`--on-accent`) |
| `--brand-radius` | optional | `10px` | Overrides `--radius-md` (default control radius) |
| `--brand-font` | optional | Plus Jakarta Sans stack | Overrides `--font-sans` + `--font-display` |

**Derived group (light, `[data-brand]`):** `--accent`=`--brand`; `--accent-hover`=mix brand+black 12%; `--accent-active`=mix brand+black 22%; `--accent-soft`=mix brand 12%+surface-card; `--accent-soft-text`=mix brand+text-primary 32%; `--focus-ring`=mix brand 24%+transparent; also rewires `--text-link`, `--border-accent`.

**Derived group (dark, `[data-theme="dark"][data-brand]` / descendant):** brand is lightened via `white` mixes (hover +26%, active +38%, soft 18%, soft-text +45%, focus-ring 30%, link +40%).

**Validation contract (D-04):** a saturated example brand **`acme` (teal, e.g. `--brand: #0D9488`)** is exercised by **Browser Mode** tests in **both light and dark**, asserting the derived `hover / active / soft / focus-ring` group resolves correctly via `color-mix`. jsdom is unusable here (renders no CSS, no `color-mix`) — Vitest + Playwright chromium is the vehicle. There is **no importable `./brands/*.css` subpath**; the canonical "make your own brand" documentation is a copy-pasteable `[data-brand="acme"]` block in the **README** (the stripped inline `brand.css` comments migrate there, per D-03a).

## Registry Safety

No shadcn registry is used (shadcn not initialized; Tailwind/shadcn-as-framework locked out). The only shadcn artifact is the **outbound compat layer** `compat-shadcn.css`, which is authored in-repo (copied from `handoff/tokens/compat-shadcn.css`), not pulled from any registry — so the third-party registry vetting gate does not apply.

| Registry | Blocks Used | Safety Gate |
|----------|-------------|-------------|
| shadcn official | none | not applicable (no registry consumed) |
| third-party | none | not applicable |

**`compat-shadcn.css` contract (opt-in, outbound):** maps shadcn's semantic CSS vars (`--background`, `--foreground`, `--card`, `--primary`, `--secondary`, `--muted`, `--destructive`, `--border`, `--input`, `--ring`, `--radius`, …) to Lyra tokens via `var()`, under `:root, [data-theme="dark"]`. Ships as an explicit subpath (`./compat-shadcn.css` or `./compat/shadcn.css` — cleaner exports entry chosen at planning), **never** imported by `styles.css`.
