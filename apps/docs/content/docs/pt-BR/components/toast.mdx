# Toast

Toast confirma que algo aconteceu, longe de onde aconteceu. Decida se a pessoa vai precisar da
mensagem depois de seguir adiante — se não, diga inline e poupe a interrupção.

## Exemplos

<Example id="basic" title="Um toast sozinho" layout="plain">
  O botão de fechar só existe quando você passa `onClose`. Um toast sem ele precisa sumir sozinho;
  um toast com ele ainda não pode ser necessário fechar para a interface fazer sentido.
</Example>

<Example id="in-a-stack" title="Dentro de um ToastStack" layout="row">
  `ToastStack` é o container fixo no canto inferior direito, e é ele que impede vários toasts de se
  cobrirem. Aperte o botão mais de uma vez para vê-los enfileirar.
</Example>

## Quando usar

Use Toast para uma confirmação breve e não bloqueante de algo que a pessoa acabou de fazer, quando ela
não precisa agir sobre isso.

Procure outra coisa quando:

- **A mensagem é sobre conteúdo da página** — use Alert, que fica ao lado dele.
- **Algo precisa de decisão antes de continuar** — use Dialog. Um toast pode passar despercebido.
- **A mensagem carrega informação que alguém vai precisar depois** — um toast que sai leva junto.

## Acessibilidade

- Standalone React Toast uses `role="status"`. Inside ToastStack it has no individual role; the
  persistent region owns announcements. ToastProvider separates polite info/success from assertive
  danger. Never put the only copy of important information in a toast.
- `ToastStack` é `position: fixed` no canto inferior direito da viewport. Ele fica por cima do que
  estiver ali, então mantenha os toasts curtos e poucos.
- O botão de fechar só aparece com `onClose`, e o nome acessível dele tem como padrão a string em inglês
  "Close notification"; passe `closeLabel` para traduzi-lo em um produto localizado.
- `tone` colore apenas o ícone. As palavras precisam dizer se algo deu certo ou errado.

## Timing and dismissal

React `ToastProvider` and the Alpine toast store resolve duration when a notification is queued:
per-toast `duration` overrides explicit provider/store configuration, which overrides the implicit
tone policy. Info and success default to **8000 ms**; danger, including `error()`, defaults to
**persistent**. `0` always means persistent. Explicit global `8000` also makes danger expire.
Changing configuration affects new notifications only.

Pointer hover and focus inside a row independently pause its remaining time. The countdown resumes
only after both leave; moving between descendants does not restart it. Give action-bearing React
messages an explicit `{ duration: 0 }`; the provider does not inspect their content.

Dismissing a focused row returns focus to its enqueue-time opener if that element is still eligible.
Removed, disabled, hidden or inert openers, and openers inside a toast stack, use the same persistent
stack instead. This named region (a landmark) remains focusable and visibly outlined even when empty.
Unfocused dismissals do not move focus, and deliberate action focus moves are preserved. The region adds no
live announcement; polite and assertive regions announce additions only.

**Migration:** set `duration={4000}` on React `ToastProvider` or assign
`Alpine.store('lyraToasts').duration = 4000` to restore the previous default delay for all tones.
Per-toast overrides still take precedence. These timing changes apply to React and Alpine; the
imported Blade API below is unchanged.
