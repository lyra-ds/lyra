# Tooltip

Tooltip adds a short hint to a control that already has a name. Decide first whether the hint should
be visible copy instead — a tooltip is the weakest place to put anything a person must read.

## Examples

<Example id="button" title="On a button">
  Pass one focusable element as the child. The component adds `aria-describedby` to it, so the hint
  reaches keyboard and screen-reader users, not only the mouse.
</Example>

<Example id="icon-button" title="On icon-only controls">
  The icon button's `label` is its name; the tooltip is the extra sentence. They are different jobs,
  and a tooltip must never be the only place a control's name exists.
</Example>

<Example id="overflow" title="Inside scrolling navigation">
  Set `escapeClipping` to keep a hint visible beyond an overflow or scroll container. Try the icons,
  scroll the rail, and switch its scoped theme or direction. The hint stays within the visual
  viewport.
</Example>

## When to use

Use Tooltip for a brief clarification of a control whose purpose is already conveyed by its own name
or icon.

Reach for something else when:

- **The text is the control's name** — use `IconButton`'s `label`, or a visible label.
- **The content is long, or contains a link or a button** — tooltips are brief, non-interactive hints. Use Dialog or inline copy.
- **The information matters on a touch device** — there is no hover there, and a tooltip that only
  opens on focus is easy to never see.

## Accessibility

- By default, CSS draws the visible bubble from `data-tip`; a separate hidden
  `<span role="tooltip">` supplies the accessible description. The open React bubble accepts pointer
  hits, so moving from the target onto the hint keeps it open during the existing leave grace.
- With `escapeClipping={true}`, a real, non-focusable `<span role="tooltip">` enters the browser's
  top layer. It remains inside the wrapper in the DOM, preserving scoped theme, brand tokens, fonts
  and direction, including changes while open. It wraps long labels and clamps its bounds to the
  visual viewport. Both modes merge `aria-describedby` with your child's existing description.
- The clipping-safe mode can use another side or a shorter scrolling hint to keep its target reachable.
- `tip` remains a plain string: neither mode supports interactive content or moves focus into the hint.
- It opens on hover **and** on focus. `Escape` dismisses it without moving the pointer — WCAG 1.4.13
  asks exactly that of content shown on hover, and the listener is on the document, because a tip
  opened by hovering never has focus inside it to receive the key.
- `placement` picks the side (`top` by default). It is a preference, not a guarantee: the tip flips
  to the opposite side on its own when the chosen one would be clipped, measured against
  `visualViewport` so an iOS toolbar or pinch zoom cannot make an off-screen tip look like it fits.
- **Pass one focusable element.** Wrapping a bare `<span>` produces a mouse-only tooltip with no
  keyboard path to it.
- **In the Next.js App Router, keep the Tooltip and its child in the same client component.** The
  `aria-describedby` is added by cloning your element, and a child that crosses the server/client
  boundary arrives already serialized: the attribute is missing from the server HTML, React reports a
  hydration mismatch, and — because React does not patch attribute mismatches — the description never
  reaches the DOM at all. A `'use client'` directive on the file that renders both is the fix.

`escapeClipping` is opt-in and defaults to `false`. The default keeps the existing CSS-drawn markup
and behavior; the public ref still targets the wrapper span in both modes. Use the opt-in for scroll
or overflow ancestors: a higher z-index alone cannot escape their clipping. Opening and closing use
the same delays, hover transit, focus handling and Escape arbitration. This is a React capability;
canonical HTML, Alpine and Blade contracts are unchanged.

The wrapper carries the text in `data-tip`; CSS draws the bubble from it:

```html
<span class="lyra-tooltip" data-tip="Everyone in the workspace can open this link">
  <button
    class="lyra-btn lyra-btn--secondary lyra-btn--md"
    type="button"
    aria-describedby="tip-share"
  >
    Copy share link
  </button>
  <span id="tip-share" role="tooltip" hidden>Everyone in the workspace can open this link</span>
</span>
```
