## Decisions and context

The maintainer rejected a Linux container prerequisite and required OS-independent contribution. The old 38-task loop is suspended by this newer direction, despite its historical approval. Do not launch it. This proposal is planning only until approved. Normal routing predicts Codex/gpt-5.6-terra for all four medium tasks, and the maintainer requested independent reviews through Claude Fable 5.1 and Cursor Grok 4.6. Both reviewed the original proposal read-only using claude-fable-5-1 and cursor-grok-4.6-high, returned REVISE, and the conductor addressed their findings here. See .batuta/reviews/test-simplification-plan-review.md. This revised text has conductor validation, not a second external APPROVE verdict. No permanent routing change is authorized.

Evidence: at 9384eb3, macOS Node24.18.0/pnpm11.13.1 global pnpm test exited 1. Its failing evaluation suite reported 693 tests, 530 pass, 161 fail, 2 skipped. A canonical-TMPDIR probe isolated 11 failures including unavailable /proc/self/fd. These numbers do not establish that all failed tests are unnecessary or that excluding the experiment fixes every platform. See .batuta/v1-loop-preflight.md and its immutable raw log references. The comparison experiment was suspended when the incumbent was retained. Root pnpm test currently invokes overlay:evaluate:core:test unconditionally. CONTRIBUTING currently presents a container as the browser workflow: removing just the root experiment command would not satisfy native contribution.

Keep the inventory to one concise Markdown table by suite/requirement, not hundreds of per-test records. Categories: keep in default, explicit suspended experiment, redundant with named replacement, investigate. Do not add a catalog generator, audit schema, report validator or new test orchestration package. Investigate only dependencies needed to decide scope. Reuse the actual preflight failures instead of repeating expensive known failures for documentation. Add regression cases only when they protect a changed behavior or failure propagation.

**Task 1.** Explicitly inspect the mixed `tools/overlay-foundation-evaluation/repository-policy.test.mjs`: script wiring, workspace integration prohibition and experiment threat-model checks do not necessarily have the same lifetime. Classify its obligations individually before excluding its entry. A threat-model assertion about a suspended harness is not automatically a general product requirement. Keep every identified active obligation reachable from the default gate.

**Task 2.** Do not delete or port the evidence writer or its tests. Update the directly coupled ordering assertion in `tools/phase1/browser-config.test.mjs` and the root-script assertion in `tools/overlay-foundation-evaluation/repository-policy.test.mjs` to the approved command contract. Retitle the misleading Docker-only test to describe separate browser execution and serialized workspace tests, preserving its actual assertions. These are changed-contract tests, not authority to relax unrelated checks. Remove experiment coupling only if task 1 proves that active requirements have no dependency on it. If an active obligation is inside that suite, identify its minimal preserved entry before changing the default. If separating it requires source edits outside this scope or a new security design, stop with a narrowly scoped follow-up proposal. A platform skip, swallowed failure or changed assertion is not a fix. Run the resulting full default command once in a clean owned checkout with a frozen install. A remaining unrelated or portability failure is a real blocker, not permission to enlarge this task or certify success.

**Task 3.** Leave `.github/workflows/ci.yml` and `tools/phase1/browser-matrix.*` untouched, including required contexts lint/typecheck/test/build and pinned Linux reference qualification. Add only `.github/workflows/native-contributors.yml` with uniquely named native checks, no container stanza, and no claims that those checks are already required or passing. Reuse existing pnpm/Playwright tooling and pin versions from the repository. Document native browser installation with `pnpm exec playwright install chromium firefox webkit` and existing `pnpm test:browsers` as a separate behavior-change check, not part of the ordinary non-browser gate. Container reference qualification remains CI infrastructure, never a contributor prerequisite. A native engine installation or test failure records the exact command, engine, exit and missing requirement and blocks that engine claim; do not create partial-pass artifacts or silently skip it. Check Windows shell/path/glob semantics instead of assuming Unix scripts work. Validate local native browser commands where available without container operations. Do not promise identical engine coverage on every OS without evidence. CI configuration alone is not a passing Windows/Linux run. Do not dispatch remote workflows or alter branch protection. Unexpected source portability work becomes one bounded follow-up with the exact failure, rather than a broad infrastructure rewrite. Cross-platform support remains unverified until each required native check actually passes on that OS.

**Task 4.** Preserve component contract, accessibility, touch, bundle/runtime and package compatibility requirements. Reuse applicable Dialog/Drawer and React18/19 evidence with exact source/artifact identity. Preserve accepted composition budget exceptions, deferred Blade scope, immutable baselines and all historical evidence. Do not infer obsolete product coverage merely because its producer lives in an experiment directory.

Execution begins interactively through Batuta: the current global gate is known to fail, so this plan cannot honestly bootstrap itself through an unattended loop. Documentation-only inventory is reviewed as documentation, not reported as a passing global gate. Task 2 requires the changed full pnpm test to pass before acceptance. Only then reassess loop preflight. No changes to the Batuta Test profile, routing, resources, releases, lockfiles or product code in this plan. No push, merge, publication or remote CI dispatch.

Stop after these four bounded tasks and the replacement proposal. Do not execute the former 38 tasks, invent a new framework, delete suspended historical experiments or implement cross-platform security primitives speculatively.
