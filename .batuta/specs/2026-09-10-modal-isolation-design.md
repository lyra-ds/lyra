## Internal ownership contract
Keep the existing modal implementations and compose a private shared modal ownership primitive. Every logically active modal has a stable cycle identity, explicit React parent modal identity and owned panel/overlay refs. Parentage follows React composition through portals, not DOM containment, CSS classes, document order, focus position or callback names. A document-scoped active list determines last accepted activation; descendants outrank their own ancestors when both mount in one commit. Ordinary rerenders and StrictMode rehearsal must not reorder an existing accepted cycle. Reopening a retained exit is a fresh activation. The active claim registers once the owned portal DOM exists and is released on accepted close/unmount; the separate inactive-exit claim persists on retained nodes until unmount; no speculative render may mutate global state.

Package entries are independently bundled. The same React runtime using root and distinct component subpaths MUST share this private ownership identity and per-document registry. A narrowly versioned shared internal singleton is allowed; do not change exports/build splitting. It must be SSR-safe, avoid module-scope document/window reads and avoid retaining documents/closed nodes. No external runtime dependency or public registry/provider. This is modal ownership only, not a replacement overlay foundation.

Logical activity is accepted open AND the parent branch's accepted activity. An accepted parent close deactivates descendants in the same branch operation, even when their controlled open props remain true through the parent's exit. This does not call child onClose or mutate application state. The descendant's visual presence may follow the existing closing parent, but it cannot remain a live portal; parent reopening reactivates any still-controlled-open descendant as a new branch cycle. A sibling has no such parent relation. Controlled ignored close requests keep full ownership. Unmounting one root must release only its branch and leave unrelated modal owners valid.

## Background isolation
Use platform inert, applied in the DOM commit/layout lifetime before passive focus work. Only the topmost active modal's owned overlay branch is interactive. Walk DOM ancestry for custom portal containers and inert sibling subtrees along that path, never body/html or an ancestor containing the active branch. Preserve preexisting inert attributes and their exact values; release only attributes actually owned by this mechanism. Suspended parent modals become inert while a nested child is topmost; switching back restores the parent before child return focus. In-flow content remains part of its owner. A custom host inside a suspended parent must leave the child's ancestry path available while inactivating surrounding siblings.

Observe childList changes only while a document has active modal claims so new or moved background subtrees become isolated. Reconcile without self-triggering observer loops. Disconnected nodes/hosts, StrictMode, initially open portals, exit retention, rapid reopen and unmount must not leak inert state or observers. User-owned hidden/aria-hidden/inert ancestors are never removed to force a modal interactive. Background isolation must not alter classes, hidden, aria attributes, layout or unrelated styles.

## Focus and interaction
Initial focus and dynamic recovery run only for the topmost active modal. Suspending a parent is not closing it: preserve opener and current focus restoration context; do not rerun initialFocusTo on parent resumption. When a child accepts close, remove its isolation claim and resume the parent's branch before the existing one-shot return-focus operation. Parent-driven branch deactivation suppresses descendant return-focus attempts, leaving the parent operation to restore the external workflow. A closing non-topmost sibling must not steal focus from the surviving topmost modal. If the active modal is destroyed without accepted close, ensure the next active modal gets a safe contained destination; do not invent background return policy on final unmount.

Native inert blocks input to inactive modal scopes. Existing owner Escape, backdrop and close/command defaults also check topmost authority, preserving consumer-first cancellation and nested Escape consumption. Lower owners never dismiss from targeted synthetic dispatch. Existing focus trap/native guards/recovery are reused, not replaced. No document-capture Escape handler that preempts consumer or child-layer behavior. Topmost order must remain coherent on retained reopen; any runtime stacking synchronization must preserve consumer-owned styles and existing CSS token bases, and cannot introduce theme/geometry/motion choices. Explain the minimum implementation if needed.

Retain current refcounted scroll behavior; verify mixed compiled imports and sibling/nonfinal release. If the independent-bundle copy of useScrollLock breaks this proof, sharing its existing state through the same document owner is within scope, without changing compensation math or application style restoration. Inline CommandPalette never joins modal isolation/focus/scroll ownership.

## Binding lifecycle decisions after technical review
These resolve the implementation-order questions above; they are part of the selected design, not optional suggestions.
- Shared identity: a versioned Symbol.for key on globalThis owns one private singleton containing the React parent context and a WeakMap<Document, document state>. Each document state has exactly one active registry/reconciler/childList observer and the existing scroll lock counter/saved values. All independent bundles acquire that same object. Do not put a second observer or counter in each hook module. No module-scope DOM access; normal context provider scoping avoids cross-root or SSR-request parent leakage.
- Parent propagation: each outer modal consumes parent context and provides its stable token plus effective branch activity to its content through the existing portal. Effective open is controlled open && parent effective activity (root has true parent activity). Descendant effective-open changes are render-propagated even if its public open is unchanged. Feed effective open to existing activity/aria-modal/scroll/trap lifetime; topmost subscription additionally gates initial focus and containment. Parent suspension by a child does NOT propagate branch closed. Stable token ancestry exists before layout registration, so simultaneous descendant registration is ordered independently of bottom-up effect order.
- Commit order: register/deactivate/reconcile via SSR-safe layout/ref lifecycle inside actual portal DOM, not passive effects. Un-inert resumed targets synchronously in that phase; then passive return-focus performs its existing resolver/opener eligibility checks. No deferred reconciliation for accepted transitions. Save the opener before applying isolation can blur it; invoke the existing one-shot capture callback with that element. Initially-open parent/child commits must not overwrite each other's capture or run parent initial focus while child owns topmost.
- Attribute claims: there must be ONE shared inert writer/ledger for Lyra background-suspension and retained-exit claims. Existing useModalActivity delegates its inactive-overlay claim to it. Closing releases active isolation immediately but adds/keeps an exit claim through retained DOM lifetime. Only the final claim restores the exact pre-Lyra attribute; same-value writes by these two mechanisms must never erase one another. Ref detachment releases its exact old node claim. Direct standalone useModalActivity tests retain their local-only semantics.
- Return-focus authority: record whether this accepted closing branch owned the prior topmost (self or descendant). Only that closing branch may return focus; ancestor-driven child deactivation and a non-topmost sibling's accepted close skip both resolver/opener attempts and missing-target warnings. Resume parent/next modal before trying eligible return target. If the prior topmost unmounts without an accepted close, explicitly restore a still-safe previously focused element inside the surviving active modal, then safe default/panel, without rerunning its initialFocusTo resolver. Never rely on the parent's local MutationObserver noticing a separate body-level portal removal. Last unmount releases resources without inventing final background focus policy.
- Dismissal authority is checked synchronously against the live registry inside ALL current defaults, including CommandPalette input Escape and pick, panel Escape, backdrop endpoints and close button. Preserve input/panel dedupe, consumer cancellation and child synthetic propagation. Checking stale render-only topmost is insufficient during commit transitions.
- Stacking is behavioral synchronization, not a new visual design: retain CSS computed z-index bases and exact consumer inline z-index value/priority. Active overlay order receives a minimal numeric offset from the greatest existing modal overlay base, ensuring logical topmost paints above lower active overlays including retained reopen. Restore owned inline values on release; do not write geometry/theme/motion styles or CSS files. Inactive retained exits cannot cover the new topmost. Verify actual hit testing and restore values; no new public styling contract.
- Scroll proof is now a reproduced obligation: the fresh mixed-subpath fixture leaves body overflow hidden after all roots unmount in all six cases. Share the existing counter/restoration state; preserve compensation math. The fixture also shows child aria-modal remains active during an accepted parent close in all three nested cases and a sibling close moves focus to the external opener while another sibling is active.

Add exact tests for initially-open simultaneous parent/child entry, pre-isolation opener capture, no-warning non-topmost sibling close, retained child inert after ancestor close, hit-tested retained reopen order and nonfinal unmount restoring focus inside the surviving modal. Negative proofs retain original compiled artifacts/source. Reconcile source/compiled discrepancies rather than weakening these cases.

## Final two review resolutions
The second independent review accepted ownership and scope and requested these two precise additions; the controller accepts both without another review-only loop.
1. Initial simultaneous ancestry: capture the pre-isolation document focus for the newly opening root-most branch BEFORE any new claim in that ancestry can apply inert. A nested opening captures a real opener only when it belongs to its live parent branch; if no such prior parent destination exists (initially open parent+child), its fallback restoration context is the named parent panel. The root keeps the external captured opener. On child close, valid returnFocusTo then actual parent opener remain preferred; when neither is eligible and a parent resumes, focus its saved safe contained destination or named panel without re-running initialFocusTo and without a missing-background-target warning. A root with no valid external successor keeps the existing warning contract. Prove exact parent containment on initially-open child close and exact external opener on final root close; do not rely on mutation recovery timing.
2. Inline CommandPalette has no modal claim, so ALL its current defaults use their existing inline pass-through behavior. Only a modal palette is gated by its own topmost authority. An inline palette composed inside a modal keeps its own input Escape/pick dedupe and callback semantics and never closes the enclosing modal as a side effect. No claim does not mean disabled.

## Executable branch-order precision
Critical native/source proofs refined implementation of the existing contract without widening scope. A child activation raises its whole accepted React ancestor branch, including the ancestor stacking context, and that parent priority persists when the child closes so the parent resumes ahead of an unrelated sibling. Compare branches coherently; a pairwise ancestor override mixed with unrelated cycle numbers is not a total order. The accepted activation belongs to the outer logical owner and survives inner Portal container replacement and StrictMode rehearsal; only accepted branch close resets it. Opening a nested sibling may capture a still-valid task control in another registered portalled descendant of the same parent branch, rather than requiring DOM containment by the parent panel. Existing application inert values remain unchanged during the claim as well as after release. Loss of topmost authority revokes any pending backdrop gesture. These behaviors have focused failing-before/passing-after source proof; final compiled cross-entry evidence remains required.
