## Required behavior
While an existing focus trap is active and its panel remains connected, visible and non-inert, recover only loss of the last actually focused element owned by that panel. React/DOM removal, disabling (including disabled fieldset), hidden/style/class visibility changes, aria-hidden or inert changes within the panel must trigger live eligibility recomputation without requiring another Tab. Eligibility includes connected, actually rendered/visible, enabled and non-inert; negative-tabindex declared heading focus remains valid programmatic focus and must not be displaced merely because it is not tabbable. A still eligible active control or panel stays focused when other content is inserted/reordered/removed. Newly inserted candidates participate in later navigation/recovery; no eager initial-focus rerun.

Nearest deterministic destination: after loss, prefer the first still eligible successor of the lost control in the last observed owned candidate order, then the nearest preceding eligible candidate. If neither survives, use a newly available eligible control at the clamped previous ordinal (first if no ordinal), else the named panel. Preserve an already selected safe application destination instead of overriding it. Read candidates live for every rescue; the remembered order only defines neighborhood, never authorizes a stale target. If the invalid control is still connected and new candidates were inserted next to it, current DOM order takes precedence over remembered order and establishes its nearest successor/predecessor. No IDs or clone/wrap requirement for consumer controls.

## Ownership and lifetime
Recovery is local to the existing hook/panel. Remember only focus actually observed inside this panel, including focus already present at hook activation. A valid current focus anywhere else (another portal/layer or an intentional application destination) wins; do not steal it. A body/document fallback after owned-node loss MUST be repaired when the panel remains eligible and no valid destination already owns focus; body focus alone is not authority to focus a panel that never owned focus. Focus observed in another live modal branch must not become the parent's recovery anchor. Do not introduce a global registry or use this repair to implement background containment.
Accepted close, inactive/unmounted panels and StrictMode cleanup revoke all pending recovery. Commit-time inactivation already sets the overlay inert; recovery must honor that before passive cleanup/returnFocusTo, including fast retained reopen. No rescue into an inert/hidden/disconnected panel, no stale observer/frame operation from a former cycle, no changes to initial/return focus timing, scroll/presence, current native Tab boundaries, Escape or consumer cancellation. All resources cleaned up. Mutation notifications must not loop due to the hook's own guards/focus updates. No global document observer, interval/polling or new dependency. This slice observes local DOM/attribute mutations; global stylesheet/media-query-only visibility changes without local mutation remain outside this local recovery mechanism and must not be represented as proven.

## Technical review resolutions (all nine findings accepted)
- Connected invalid anchor: current DOM order takes precedence, choosing next eligible existing Tab candidate, then previous. Detached anchor: last observed owned candidate neighborhood defines next surviving successor, then preceding survivor, then clamped ordinal among new candidates, then panel. Include the actually observed anchor at its DOM position even when it is absent from the Tab selector (negative-tabindex heading, contenteditable, summary or media control). This adds no new navigation candidates. Explicitly prove heading removal and retention.
- Loss means failure of a unified programmatic-focusability plus eligibility predicate, consistent with the existing initial-focus helper's semantic categories: valid tabindex, native controls/links, top-level contenteditable, first summary, media controls. Local attribute observation includes href/contenteditable/tabindex changes, not only the listed examples. Unknown attributes may change CSS and must not silently bypass recomputation. Fieldset disabling is tested through :disabled in the existing Tab eligibility filter too; this necessary predicate correction is in scope.
- At rescue time any valid active element (inside or outside the panel) other than the now-invalid anchor wins. Eligible current panel also stays. Exclude body/html and owned temporary focus-boundary guards as authoritative destinations; pending native-boundary navigation settles through its existing owner before rescue, without a new timing loop.
- Local modal branch discriminator follows existing initial-focus ownership: a descendant's closest('[role="dialog"][aria-modal="true"]') must be this panel whenever a modal branch exists; generic direct hook fixtures without aria-modal still distinguish descendant dialog branches from their own panel. Parent must never record child branch focus as its anchor or recover on that child's loss.
- Ancestor panel invalidation is not promised as an observed local mutation; every rescue checks panel visibility/connection/inert/hidden and no-ops when invalid. Commit-time inert on logical close defeats pending rescue before passive cleanup.
- Add explicit recovery-specific tests: body-only without previously owned focus does nothing; child-only focus followed by removal does not arm parent; commit-time inert prevents rescue; retained reopen and StrictMode cleanup cancel old work; observer notifications settle without a loop. Tests use actual focus/DOM and native MutationObserver, not mocked delivery or sleeps. Bound stale-work proof to observable focus outcomes and owned resource cleanup rather than implementation-mirroring tests.
