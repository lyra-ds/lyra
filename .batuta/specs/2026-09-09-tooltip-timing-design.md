# Tooltip timing and ownership — incumbent correction

Status: implementation authorized by the maintainer's continue-until-completion direction; technical verification and independent review pending. This implements the existing Tooltip timing requirements, with no public API migration or new runtime library. Source cause and native12-case RED are in v1-tooltip-timing-diagnosis.md.

## Scope and retained surface
Keep TooltipProps, root/ref/id/class/placement conventions, semantic child native action, stable describedby merge and existing placement owner. Preserve CSS handoff verbatim. Add CSS only at feedback.css's additive end, with existing parity policy. Keep current pseudo-element visual and hidden role=tooltip description node for this bounded task; no portal, replacement foundation, new global event framework or duplicate visible DOM. Existing exact placement and Escape-opacity tests remain. Broader clipping/screen-reader qualification is not claimed by this timing repair.

## Ownership and clocks
Use one private coordinator per actual root.ownerDocument, held in a WeakMap<Document,...>; acquire/release through instance lifecycle. Each registered Tooltip keeps its own pending500ms open and100ms pointer-leave timers. The document owner stores warm state, visible opening order, registered instance ownership and one300ms expiry timer. Use the associated document window for clocks/listeners. Do not export a public coordinator/provider or change the package export map. One small internal module is allowed if it keeps the component readable; no generalized overlay manager.

Focus in the trigger/tooltip branch opens immediately without moving focus. A cold mouse/pointer hover schedules500ms; no visible state at499ms, open at500ms. While warm, hover opens synchronously in the same input turn without scheduling500ms or0ms timeout. Any logical open warms the document. The300ms expiry begins only after the last logical visible close AND no registered trigger/bubble retains hover/focus ownership. Opening or retaining ownership cancels expiry. A later last close starts a fresh300ms; at299ms warm, at300ms cold. An instance's pending cold hover must not be cancelled merely because a different instance is pending. Final registered-owner destruction cancels all pending timers/listeners and resets cold; remount starts cold, including StrictMode cleanup safety. Distinct documents never warm each other.

The wrapper owns the combined focus/hover branch. Avoid duplicate child+wrapper internal show/hide paths; preserve child consumer handlers and wrapper consumer handlers exactly once with their normal event delivery. Focus moving inside the branch is not an exit. Blur outside closes immediately unless hover remains. Hover leaving both trigger and pseudo-bubble cancels pending open, and retains an already-visible tooltip for100ms unless focus remains; a reentry during grace cancels close. Focus ownership alone survives pointer exit. Do not invent a tab stop on the wrapper/bubble.

## Actual hover surface
The state-open pseudo-element must remain visibly open independently of :hover/:focus-within during100ms grace. Give ONLY the state-open React-owned pseudo-element pointer events so native entry onto the bubble participates in wrapper hover; state-closed content must not intercept input. Preserve top/bottom/left/right transforms, theme styling and existing transition. Raw CSS-only/Alpine tooltips without React data-state keep existing behavior. Prove this with native coordinates over the actual rendered pseudo-bubble, not a synthetic mouseenter alone. If actual pseudo hit testing cannot meet this on all3 engines, stop and report the result before migrating visual DOM or public behavior.

## Dismissal and teardown
Escape dismisses the most recently opened visible Tooltip in the same document only, once, without moving focus or invoking native click. Use document handling for hover-only content and the root keyboard route for focused branches so existing focused Escape containment remains. Both routes share one decision; honor consumer preventDefault and never dismiss a second tooltip from the same event. Preserve child/root keyboard consumers. No listener remains when no tooltip is visible; no timer can revive a dismissed tooltip while the same ownership persists. Escape suppression clears only after that instance's focus and hover owners have left, so stationary input cannot reopen it. Retained owners still prevent warm expiry; expiry starts when they leave and no visible tooltip remains. Do not close unrelated overlays or assert a new global cross-family ordering contract.

Close, tip replacement, actual target removal and unmount cancel pending opens/closes and owned placement/listener work. Verify target connectivity and current content/cycle before delayed open; stale closure cannot expose replacement or removed content. Avoid using ReactElement object identity as removal detection because an ordinary parent render creates a new element. Keep timer cancellation/registration correct under StrictMode, final unmount and document separation. A replacement's fresh input may open its current text normally.
