## Evidence and cause
At source599d62f, existing DataTable source tests7/7eachengine pass, but compilednative proof reproduces pointer-only row command and opaque-cell double action. onRowClick is attached directly to tr; row has no native activation semantics. ## Selected minimum contract
Remove DataTableProps.onRowClick and the DataTable-owned tr click handler. There is no replacement row-wide click handler, row keyboard shim, interactive tr role, row tab stop, event-target selector/filter, child cloning, generic action manager or new rowAction/renderActions API. The existing columns plus ReactNode row values are sufficient to render explicit semantic action cells. Consumers supply a native button for an operation or a native link for navigation, with a visible accessible action name including row identity when needed. Native button Enter/Space and pointer click invoke that one consumer action; links retain ordinary navigation. Consumer disabled/preventDefault/native handlers remain native; DataTable does not attach another domain action to the row.

Keep sort and selection exactly as they are, including controlled/uncontrolled callbacks, existing checkbox propagation behavior, row-ID sorting semantics, ARIA and states. Arbitrary rich cell children are opaque and untouched. Plain cells and tr do not become commands. hover remains an explicit visual boolean, no longer implied by the removed callback. Root div/ref/native props, current classes, layout, loading/empty/footer and data models remain. No CSS change or Alpine runtime support is introduced. Existing app-level root onClick remains a native consumer prop, not a supported replacement for row activation.

## Alternatives declined
A new rowAction descriptor/renderActions API duplicates the existing ReactNode cell capability and adds labeling/layout/disabled/public-type contracts without a demonstrated missing capability. Keeping onRowClick plus interactive-target filtering still retains a pointer-only action and cannot close the P1. Making tr into a button/grid row harms native table semantics; wrapping arbitrary cell content could create nested controls. Merely updating prose while retaining the unsafe API is insufficient: remove its source/type behavior and prove the real first-party semantic replacement.
