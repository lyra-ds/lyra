Native baseline at3c000ab has9/9 failed criteria across3 engines: create is option4 inside the listbox, End focuses Create, Tab closes before Create. ## Problem and sources
The current React popup exposes the create button as an unselected listbox option. It participates in arrows/Home/End although it invokes onCreate rather than choosing a workspace. Simply removing its option role is insufficient: the current option Tab handler closes before keyboard users can reach the command.
The retained OF-COMPOSED contract owns workspace selection separately from consumer change/create effects (docs/superpowers/specs/2026-08-30-overlay-family-design.md:428-432). The W3C APG listbox pattern describes selectable options and separate command controls: https://www.w3.org/WAI/ARIA/apg/patterns/listbox/ (read September9,2026). This design applies those semantics to existing support; it does not introduce a grid or new variant.

## Structure and compatibility
Keep the outer .lyra-wssw__pop, ref and placement measurement. Put actual workspace options in a labelled inner listbox with the existing listbox ID. Keep the visible Workspaces label and existing classes/layout; the create button and separator remain within the visual popup but outside the listbox. The real type=button create action has no option role or aria-selected. Public props/ref/callback signatures, current ID ownership, selection computation, classes, flip behavior and create label remain. No styles should be required; existing item width and popup layout must be verified visually and by axe. Consumers using a direct-child DOM selector may need to target the unchanged .lyra-wssw__item class; document this structural correction in the changeset.

## Keyboard and focus
Opening enters the selected workspace, falling back to first. An empty workspace list with a create action enters that action; an entirely empty popup must not move focus to body and Escape from the retained trigger must close it. Arrows/Home/End move only among workspace options without changing selection or invoking callbacks. Exactly one existing workspace option is in sequential Tab order, tracking actual focused option; all other options are programmatically focusable but excluded from that sequence. The create button has an explicit native Tab stop.
With creation present, native Tab from a focused option reaches Create; Shift+Tab from Create returns to the current roving option. If no workspace option exists, it exits backward to the trigger and closes. Tab from Create exits to the next external stop and closes without restoring focus. Shift+Tab from an option returns to the trigger and closes. Without creation, Tab retains current close/native-exit behavior. No forced external focus, timing sleep or preventDefault for unmodified Tab. Escape from either domain restores the trigger. Enter/Space/click on Create invoke onCreate once, never onChange; workspace activation invokes the existing onChange once. Consumer cancellation from Task21 runs before defaults, including Escape/Tab. stopPropagation alone is not cancellation. Mouse/touch activation must survive normal WebKit focus behavior.
No general blur-close is prescribed: it must not unmount the clicked command before a WebKit pointer click. Current outside-mousedown ownership remains; no new global observer or focus infrastructure.
