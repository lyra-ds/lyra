Arquitetura & Distribuição

Fundamentos do Lyra como design system open source, multi-stack e white-label — revisado jul/2026.

Camadas de token

1 · PrimitivasEscalas cruas: --indigo-600, --space-4, --text-2xl. Nunca usadas por componentes.
2 · SemânticasIntenção: --accent, --surface-card, --text-muted. Única camada que componentes consomem. Temas e marcas trocam só esta camada.
3 · ComponentesClasses .lyra-* com variantes por modificador (--primary, --sm). Sem cor ou raio hardcoded.

Decisões (vs. shadcn)

CSS puro

Sem Tailwind no core. CSS variables + classes funcionam em React, Vue, Svelte e Web Components — a base do requisito multi-stack. Um preset Tailwind pode ser publicado depois como pacote satélite.

Naming Lyra

Mantemos a nomenclatura semântica própria (mais rica que a do shadcn) e oferecemos tokens/compat-shadcn.css opt-in que mapeia --background, --primary, --ring… para tokens Lyra — componentes do ecossistema shadcn rendam com a pele Lyra.

Zag.js

Comportamento acessível via state machines agnósticas de framework (base do Ark UI; suporta React/Vue/Svelte) em vez de Radix (React-only). O core CSS não depende disso.

LLM-first

API canônica para agentes em llms.txt (raiz), gerada dos .d.ts reais: regras de geração, tokens semânticos e props de todos os componentes. Fase 2: registry com metadados por item + MCP server para instalação via agente.

White-label

Contrato em tokens/brand.css: a marca define --brand, --brand-contrast, --brand-radius, --brand-font sob [data-brand="x"]; todo o grupo accent (hover, active, soft, focus-ring, link) é derivado via color-mix, em light e dark. Prova viva em explorations/multibrand-demo.html.

Distribuição — duas vias, não excludentes

  • npm: @lyra-ds/core (tokens + CSS, zero JS) · @lyra-ds/react · depois @lyra-ds/vue, @lyra-ds/svelte, @lyra-ds/wc — adapters finos sobre o mesmo CSS.
  • Registry estilo shadcn: registry.json servindo os componentes React como código copiável (npx shadcn add @lyra/button). Ownership do código para quem prefere.

Recomendação: lançar npm core+react primeiro; registry como segunda fase reaproveitando os mesmos fontes.

Estrutura de repositório proposta

  • packages/core — tokens/, components/*.css, brand.css, compat-shadcn.css
  • packages/react — wrappers JSX (os 40 atuais)
  • packages/{vue,svelte,wc} — fase 2, sobre Zag.js
  • apps/docs — site + registry
